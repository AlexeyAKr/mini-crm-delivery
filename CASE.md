# Кейс: Mini-CRM доставки ChinaGoods

## Проблема и пользователь

**Пользователь:** менеджер небольшого магазина ChinaGoods — один человек, совмещает роли владельца, продавца и логиста.

**Проблема:** заявки приходят из Авито, Telegram и по телефону. Каждая живёт в своём чате, статус заказа помнится «в голове». Когда клиент звонит и спрашивает «где моя посылка?», менеджер тратит время на поиск по перепискам. Нет единой картины: сколько заказов за день, на какую сумму, сколько доставлено.

**Что изменило приложение:** все заказы собраны в одном месте со статусами, поиском по телефону, фильтрами по дню и сводкой дня.

## Выбранный MVP

Главный сценарий: менеджер создаёт заказ, проводит его по статусам, находит по телефону, видит сводку дня.

Что осознанно не вошло:
- Многопользовательский режим с ролями и логинами
- Курьер-режим
- Автоимпорт заявок из Telegram-бота и Авито
- Расчёт стоимости в юанях с учётом веса
- Дашборды и графики за месяц

## Что реализовано

**Работа с заказами:**
- Создание заказа: клиент, телефон, адрес, состав, сумма, канал (avito / telegram / manual), трек-номер, поставщик, комментарий
- Редактирование существующего заказа
- Поиск по телефону в любом формате (+7, 8, с пробелами, скобками, дефисами)
- Фильтры: по периоду (сегодня / 7 дней / всё время), статусу, каналу
- Сводка дня: количество заказов, сумма, доставлено, отменено

**Статусная модель:**
- Цепочка новый -> подтверждён -> в пути -> доставлен
- Отмена из любого статуса, кроме финального, с обязательным указанием причины
- Защита от перескоков и откатов
- История статусов: каждая смена записывается с датой и комментарием

**ИИ-разбор заявок (GigaChat):**
- Менеджер вставляет текст сообщения клиента — GigaChat заполняет поля формы автоматически
- Если GigaChat недоступен — форма продолжает работать, менеджер заполняет вручную

**Предоплата:**
- Автоматическая подстановка 50% от суммы заказа
- Ручная правка возможна, с валидацией: 0 <= предоплата <= сумма

**Защита от дублей:**
- Двойной клик по «Сохранить» не создаёт две заявки

## Как проверялось

**Автотесты: 64 штуки, все зелёные (pytest tests/ -v):**

- Статусы — 26 тестов: разрешённые переходы, запрещённые, откаты, отмена
- Телефон — 13 тестов: нормализация в 7+ форматах
- Заказы — 15 тестов: CRUD, сводка дня, предоплата, поиск
- Навигация — 16 тестов: переходы между страницами, автоподстановка, защита от дублей
- ИИ-парсер — 4 теста: извлечение JSON из ответа GigaChat

**Ручной прогон главного сценария:**
1. Создание заказа через ИИ-разбор
2. Проведение по всем статусам до «доставлен»
3. Поиск по телефону
4. Проверка фильтров и сводки
5. Проверка отмены с причиной

Все шаги прошли успешно.

## Что было самым сложным

**Streamlit.** Главная проблема — навигация между страницами и сохранение состояния формы. В Streamlit при каждом действии пользователя скрипт перезапускается с нуля.

Что пришлось решать:
- Передача order_id между страницами через st.session_state и st.switch_page
- Защита от повторной отправки формы через флаг в session_state
- Автоподстановка предоплаты с сохранением ручной правки
- Понимание, что блок if submitted: внутри формы не работает после st.rerun()

Отдельная сложность — миграция на библиотеку gigachat версии 0.2.3: изменился API вызова (chat.create вместо chat), формат ответа и обязательное указание модели.

## Что улучшу дальше (вторая версия)

**Автоматизация входящих заявок:**
- Подключение Telegram-бота ChinaGoods — заявки попадают в CRM автоматически
- Возможное подключение к API Авито

**Расширение статусной модели:**
- Промежуточные статусы: выкуплен, на складе РФ
- Подстатусы для отменённых: отказ клиента, потеря посылки

**Работа с деньгами:**
- Расчёт стоимости в юанях: юань x курс + вес x тариф

**Курьер-режим:**
- Отдельный экран для курьера: список заказов на день
- Экспорт маршрута в Telegram

**Аналитика:**
- Дашборд за 30 дней
- Сравнение каналов по конверсии

**Инфраструктура:**
- Переход с SQLite на PostgreSQL для многопользовательского режима
- Развёртывание на российском хостинге

## Ограничения

- Публикация на Streamlit Cloud недоступна из России — демонстрация через видео
- SQLite на бесплатных хостингах теряет данные при перезапуске контейнера
- ИИ-разбор работает только с текстом
- Данные хранятся локально, синхронизации между устройствами нет
